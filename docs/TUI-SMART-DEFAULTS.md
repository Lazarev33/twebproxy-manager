# TUI: стандартная и расширенная настройка

Кандидат 0.2.26-beta; изменения пока не установлены на рабочих Entry/Exit.
Запускайте Manager из полного проверенного дистрибутива с `bridge/` и `sites/`.
Один скачанный Bash-файл не заменяет пакет с проверяемыми зависимостями.

## Первая установка

В главном меню выберите быструю настройку и введите публичное доменное имя.
Manager проверяет DNS, инструменты, управляемый frontend и занятость портов.
Стандартная настройка использует bundled-сайт «Культурные маршруты Подмосковья»,
HTTPS, профиль `default`, случайный secret и проверенные внутренние порты.
При отсутствии managed frontend выбирается Caddy. Совместимый managed frontend
можно использовать повторно. Контакт ACME не выдумывается: для Nginx нужен уже
проверенный контакт либо расширенная настройка.

Перед установкой отображаются домен, выбранные компоненты и последствия для
соединений. Требуется явное согласие. Пустой ответ и EOF не разрешают изменение.
Активный UFW отдельно запрашивает разрешение открыть публичные TCP 80/443.
Неизвестный владелец этих портов или неподтверждённый DNS останавливают Quick.
Исправьте DNS/конфликт либо выберите расширенную настройку; проверки не обходятся.

Расширенная настройка сохраняет выбор собственного каталога, upstream-сайта,
Caddy/Nginx/внешнего TLS, внутренних портов, профиля, secret и лимитов.
Автоматическая проверка доступности порта повторяется под существующей блокировкой
при резервировании: предложенный порт не считается зарезервированным заранее.

## Профили и обслуживание

Стандартный дополнительный профиль получает свободное имя `profileN`, случайный
secret, HTTPS, один worker и лимит 4096. Расширенный режим оставляет ручные поля
и готовый вариант двух workers. Один однозначный объект выбирается автоматически;
при нескольких объектах остаётся нумерованный выбор. Цель видна перед изменением.

Ротация предлагает новый случайный secret или ручной ввод. Изменение carrier,
ремонт, перезапуск, обновление, продление сертификата и удаление требуют согласия.
Изменённые пользователем файлы сайта сохраняются при repair. Явное удаление
инстанса удаляет и его сайт — это по-прежнему разрушительная операция.
Диагностика запоминает выбранный hostname до выхода из раздела; его можно сменить.
Полный отчёт требует согласия из-за чувствительных данных.

Ошибка операции показывает причину и исходный код, затем возвращает меню.
Операция выполняется в отдельном Bash-процессе с обычным `errexit`: ошибка внутри
не должна разрешить последующие шаги. CLI сохраняет свои команды, форматы JSON/raw
и ненулевые коды; возврат TUI к меню не превращает CLI-ошибку в успех.

## Совместимость сети

Раздел предлагает статус, пошаговый выбор, возврат STOCK и расширенный выбор.
Все шесть существующих методов сохранены: STOCK, Window 1152, MSS 88, nfqws,
Window + nfqws, MSS + nfqws. Вводить параметры пакетов не требуется.
STOCK остаётся безопасным исходным вариантом. Сервер не определяет надёжно DPI
в сети клиента; выбор не сопровождается обещанием автоматической диагностики.
Применение метода и возврат STOCK требуют согласия на общий IPv4 scope.
Существующие сетевые транзакции и откат не изменены.

## Зарубежный узел

При отсутствии узла меню предлагает добавление; при существующем узле или долге
очистки — статус, диагностику, восстановление и удаление. Состояние не удаляется
ради повторной установки; контроллер дополнительно проверяет ограничение одного узла.

Обычно нужны адрес, выбор стандартного SSH root:22 либо других параметров,
пароль/путь к защищённому существующему ключу, независимо сверенный отпечаток и
одобрение плана. Для единственного hostname повторный выбор не нужен.
Пароли и passphrase скрыты, остаются в памяти; пустой пароль отвергается.
Неизвестный SSH-ключ автоматически не принимается. План описывает службы,
доверие к foreign root, влияние procfs и компенсацию частичной установки;
клиентские ключи в нём не показываются.

## Проверка и ограничения

См. `docs/PRERC-v0.2.26.md`, `TUI-INPUT-INVENTORY.md` и результаты в архиве.
Исторический отчёт первого кандидата сохранён отдельно в provenance архива.
Linux-интеграция выполнена в отдельной Ubuntu 24.04 KVM VM. Успешная новая Quick
установка с публичным сертификатом, новое двухузловое развёртывание, парольная
SSH-аутентификация и Telegram-приложение для этой версии не выполнялись.
Ранее принятые результаты Gate3 относятся к 0.2.25-beta, а не автоматически
к данному кандидату. Debian/другие Ubuntu/ARM не сертифицируются этим этапом.

## Точечная коррекция кандидата

Версия остаётся 0.2.26-beta и ещё не опубликована. Основной план согласован с
GitHub main4049dee; до stable сетевой тракт заморожен, идеи из roadmap-test.md
отложены. При подтверждении допустимы явные `y`, `yes`, `д`, `да` и регистровые
варианты. Восстановление/удаление остаются default-NO. EOF и незавершённая строка
не разрешают действие; закрытый ввод restore возвращает отдельный код 130.
Ошибки CLI завершаются исходным кодом и диагностикой stderr, без повреждения
JSON/raw stdout; ошибки TUI показываются и возвращают к меню.
