# Gate3: отказ Add завершал интерактивный Manager

База: `6f8b4b28a2ad1c4d71e6518e653fbaa7d5094ee6`, v0.2.25-beta.
Это рабочее исправление текущего Gate3, без нового релиза и без развёртывания.
Прежние Gate3/Gate2 артефакты и незакоммиченные файлы миграции сохранены.

## Причина и границы

`main menu → menu_foreign_nodes → foreign_node_cmd add → bridge_launcher →
controller.add`. Проверка `STATE.exists()` намеренно возвращает Fault до
настройки SSH, выбора профиля, записи состояния или вызова служб. Она нужна
для существующего узла, прерванной установки и незавершённой очистки.

В исходном Bash `set -Eeuo pipefail`; меню вызывало команду без проверки
результата. Возврат Python 1 вызывал глобальный ERR-handler, затем выход
Manager. Это ошибка интерактивной границы, а не нарушение ограничения одного узла.
Обе установленные копии RU Manager имеют сообщённый оператором SHA256
`6230f2e43044cd60cebf87f27aa0eee4c42ea1a4038224c3b81055d17e77ec60`,
совпадающий с исходной принятой сборкой. Затем этот хеш и прямые необработанные
вызовы меню независимо прочитаны по SSH как `twp-audit`. Живое воспроизведение
не выполнялось.

## Исправление

`foreign_node_menu_run` вызывает выбранную операцию в изолированной оболочке,
перехватывает ненулевой результат и показывает локализованную сводку с его
точным кодом. Исходные stdout/stderr сохраняются; успех при ошибке не печатается.
Явный `die/exit` проверки пакета не завершает родительский Manager.
Все пять пунктов меню используют эту границу. Неинтерактивный `foreign-node`
вызывает прежний путь напрямую: отказ остаётся 1, иные коды сохраняются.

`STATE.exists()` и обработка rollback/pending-cleanup не изменены. Отказ Add
не превращён в автоматические repair/remove и не перезаписывает узел.
Переведены русские заголовки, ожидаемые отказы, SSH-подсказки и подтверждения.
Явные `yes` и `да` подтверждают действие; пустой ответ и отрицание — нет.
Ключи/значения машинного JSON и параметры CLI остаются стабильными.
Изменение controller включено в проверяемый MANIFEST и закреплённый digest.

## Проверка

```sh
PYTHONDONTWRITEBYTECODE=1 python3 tests/bridge-gate3/test_bridge_menu.py
PYTHONDONTWRITEBYTECODE=1 python3 tests/bridge-gate2/test_safety.py
bash -n twebproxy-manager.sh
```

13 новых тестов PASS и 8 тестов пакета PASS. Процессные тесты исполняют реальные
Bash-меню/CLI и Python Add guard с временными файлами. Подменён launcher boundary;
status/diagnose возвращают фикстуры. Обращения к службам/сети запрещены ловушками.
Это локальная регрессия, а не доказательство нового развёртывания на Linux-узлах.
Проверены active/pending-cleanup, повторный показ меню, status/diagnose и возврат
в главное меню, явный exit дочерней проверки, видимый код операционного сбоя,
CLI 1/7/0, отсутствие изменений содержимого/режима/mtime/inode существующих файлов,
русская/английская локализация и подтверждения. Исходная сборка воспроизводимо
проваливает два ключевых сценария; raw red/green вывод хранится отдельно.

Удалённый `agent.py` побайтно совпадает с базой; принятые firewall/procfs функции
не изменены. Эти сравнения исходников не являются повторной приёмкой P1.

## Живое окружение и ограничения

Развёртывание исправления и разрушительное воспроизведение на живом узле
NOT_EXECUTED: отдельного разрешения на redeploy нет. Результаты прежнего Gate3
не переписаны новым утверждением о приёмке этой рабочей версии.

События MTProxy рассматриваются отдельно. По SSH независимо прочитано:
Bridge-forwarder active/success, NRestarts=0, запуск 2026-10-31 10:02:01 UTC;
relay active/success, NRestarts=0, запуск 10:02:34 UTC. Локальный fallback
MTProxy inactive/dead, NRestarts=0 — соответствует Bridge, где MTProxy работает
на зарубежном узле. NRestarts не является полной историей ручных перезапусков.
Под `twp-audit` записей запрошенного журнала не получено; причина ранее замеченных
событий и их связь с Add не установлены. Неудачные команды с разорванным именем
юнита не использованы как доказательство состояния службы.

SSH-доступ подтверждён с development VPS как `twp-audit`, UID/GID1000,
дополнительная группа users(100), без sudo. Отпечаток RU совпадает с независимо
подтверждённым. Доступны публичный Manager и свойства systemd; недоступны /root,
/etc/twebproxy и /opt/twebproxy-manager; системные конфигурации не доступны на
запись. Собственный домашний каталог доступен на запись: это обычная ограниченная
учётная запись, а не общий read-only sandbox. Выполнялись только чтения; операции
изменения служб/конфигурации не проверялись. Временный приватный ключ хранится
вне репозитория и архивов. Первичная попытка как root была отклонена; после
уточнения пользователя вход выполнен правильно как twp-audit.

Миграция сохраняется: работа продолжается на VM-192306 в исходной беседе UUID
`01a18918-f74d-7151-9afe-ea11df457034`; исходный сервер остаётся работающим fallback.
Исторический ZIP миграции не изменяется. Текущее продолжение беседы не разрешает
перезаписывать её более старым source checkpoint.
